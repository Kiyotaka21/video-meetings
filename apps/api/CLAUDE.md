# CLAUDE.md — apps/api

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Общие правила монорепозитория — в корневом `CLAUDE.md`. Здесь только то, что
касается бэкенда.

## Стек

Elysia 1.4 на Bun, Prisma 7 к Postgres. Рантайм — именно Bun, не Node: `Bun.env`,
`bun --watch`, `bun build --target bun`, `Bun.password` для хеширования. Порт 3000.

```bash
bun run --filter @video-meetings/api dev        # или из корня: bun run dev:api
cd apps/api && bun run typecheck                # tsc --noEmit
cd apps/api && bun run test                     # bun test; из корня: bun run test
cd apps/api && bun run db:migrate                # prisma migrate dev
```

| Маршрут                                                | Доступ       |
| ------------------------------------------------------ | ------------ |
| `GET /health`                                          | открытый     |
| `POST /auth/register`, `POST /auth/login`              | открытые     |
| `GET /auth/me`                                         | Bearer-токен |
| `POST /meetings`, `GET /meetings`, `GET /meetings/:id` | Bearer-токен |
| `POST /meetings/:id/files`, `GET /meetings/:id/files`  | Bearer-токен |

Контракты всех трёх доменов целиком описаны тестами — `tests/auth.e2e.test.ts`,

## Загрузка файлов встречи: сначала ресерч, потом код

Фича описана тремя документами, и роли у них разные:

| Файл                                   | Отвечает за                                               |
| -------------------------------------- | --------------------------------------------------------- |
| `docs/prd-meeting-file-upload.md`      | что и зачем, без «как»                                    |
| `docs/plan-meeting-file-upload.md`     | порядок работ по фазам                                    |
| `docs/research-meeting-file-upload.md` | чем именно и обо что споткнёмся — замеры на наших версиях |

**Перед правкой `src/modules/files/*`, модели `MeetingFile` или роутов
`/meetings/:id/files` читай ресерч целиком, а не по диагонали.** Он не
справочник «на всякий случай»: в нём результаты запусков на Bun 1.3.14 и
Elysia 1.4.30 — и шесть мест, где рантайм ведёт себя не так, как читается из
документации, поэтому план приходится править. Например, забытый `await` у
`writer.write()` даёт +2423 МБ RSS на файле 1 ГБ вместо +6 МБ, а авто-`Range` у
`new Response(Bun.file(...))` через Elysia молча отвечает 200 вместо 206.

Замер в ресерче — записанный результат запуска, а не цитата из документации.
Разошёлся с поведением — значит поехала версия: чинить надо версию или замер, а
не обходить его на месте. Найденное сверх ресерча дописывается туда же, в раздел
«Проверено замером», иначе следующий агент потратит на поиск тот же час.

## Зачем entry разбит на три файла

```
src/index.ts        только listen — точка входа
src/app.ts          сборка плагинов, экспортирует app и тип App
src/modules/        доменные модули = плагины Elysia
src/config/env.ts   всё чтение окружения
```

Разделение `index.ts` / `app.ts` не косметическое:

- `app.ts` не открывает порт, поэтому его можно импортировать в тестах и дёргать
  через `app.handle(new Request(...))` без поднятия сервера;
- `app.ts` экспортирует `export type App = typeof app` — это то, что нужно
  Eden Treaty, чтобы дать фронтенду типизированный клиент. Тип обязан отражать
  всю цепочку `.use(...)`, поэтому новые модули подключай в `app.ts`, а не
  навешивай на инстанс где-то ещё.

Новый домен — это новый файл в `src/modules/`, экспортирующий инстанс Elysia с
`prefix` и `tags`, и одна строка `.use(...)` в `app.ts`.

## Данные: Prisma 7

```
prisma/schema.prisma       модели
prisma/migrations/         история миграций, коммитится
prisma.config.ts           конфиг CLI: путь к схеме и DATABASE_URL
generated/prisma/          сгенерированный клиент, в git не попадает
src/db/prisma.ts           единственный инстанс PrismaClient
```

Четыре вещи, которые отличают семёрку от привычной Prisma и ломают код, если про
них не знать:

- **Клиент не работает без драйверного адаптера.** Rust-движка в 7 нет, запросы
  исполняет query compiler поверх драйвера, поэтому `new PrismaClient()` без
  `adapter` не заведётся. Здесь стоит `@prisma/adapter-pg` (тянет `pg` сам).
- **`DATABASE_URL` задаётся в `prisma.config.ts`, а не в блоке `datasource`.** В
  схеме остался только `provider`; строка подключения приходит из конфига через
  `env('DATABASE_URL')`.
- **CLI зовётся как `bunx --bun prisma`, и это не косметика.** `env()` из
  `prisma/config` рассчитывает, что `.env` подгрузил рантайм. Bun это делает,
  Node — нет, так что под `npx prisma` (или `bunx` без `--bun`) `DATABASE_URL`
  окажется пустым, а команда — «непонятно почему» неработающей. Все скрипты в
  `package.json` уже с `--bun`; альтернатива — тащить `dotenv` ради одного импорта.
- **Импорт клиента — из `../../generated/prisma/client`, а не из `@prisma/client`.**
  Генератор `prisma-client` кладёт исходники в `generated/`, каталог в
  `.gitignore`, `.prettierignore` и в ignores ESLint. После клона и после правки
  схемы его надо пересобрать: `bun run db:generate` (и то же самое делает
  `postinstall`, так что обычный `bun install` закрывает вопрос).

В базе имена в snake_case (`password_hash`, `users`), в коде — camelCase; связывает
их `@map`/`@@map` в схеме. Правка схемы без миграции в том же коммите — способ
получить рассинхрон, который вылезет у следующего разработчика на `db:migrate`.

## Аутентификация

`src/modules/auth.ts`, два маршрута. Что здесь сделано намеренно и не должно
«упроститься» при следующей правке:

- **Пароли хеширует `Bun.password`** (argon2id по умолчанию) — внешняя библиотека
  не нужна. В базе лежит только хеш, наружу не отдаётся даже он: ответ обоих
  маршрутов — `{ token }` и ничего больше.
- **Занятость e-mail ловится по ошибке `P2002`, а не проверкой `findUnique` перед
  вставкой.** Между такой проверкой и `create` есть окно, в которое пролезает
  второй запрос; unique-индекс закрывает его сам, а обработчик просто переводит
  P2002 в 409.
- **Логин отвечает одинаково на неизвестный e-mail и на неверный пароль** — один и
  тот же 401 с одним и тем же телом. Иначе ответ становится оракулом, по которому
  перебирают зарегистрированные адреса.
- **Пароль сверяется даже когда пользователь не найден**, с константой
  `ABSENT_USER_PASSWORD_HASH`. Без этого argon2 отрабатывает только в одной из
  веток, и тот же перебор идёт по времени ответа.
- **E-mail нормализуется в нижний регистр** перед записью и перед поиском, иначе
  `Foo@` и `foo@` заводят две учётки.

### `GET /auth/me`

Отдаёт `{ id, email }` текущего пользователя — фронтенду нужен адрес вошедшего,
чтобы показать его в кабинете. Два решения здесь неочевидны:

- **Маршрут вынесен в отдельный инстанс `currentUserRoutes`, а не дописан к
  `authModule` после `.use(authenticated)`.** Hook'и Elysia действуют на роуты,
  объявленные после них: при дописывании порядок строк в файле начал бы решать,
  открыт `/auth/register` или закрыт. Отдельный инстанс делает границу видимой —
  под guard'ом ровно то, что внутри него. Что register и login остались
  открытыми, проверяют их собственные тесты: они ходят без токена.
- **Годная подпись при отсутствующем пользователе — это 401, а не 404.** Учётку
  удалили или токен выпущен против другой базы; для клиента это ровно та же
  мёртвая сессия, что и истёкший `exp`. Один код на все случаи позволяет
  фронтенду держать одну ветку «401 → выйти и на /login» вместо разбора 404,
  который иначе выглядел бы как «такой страницы нет».

Адрес берётся из базы, а не из `email` в payload'е токена: иначе `/auth/me`
подтверждал бы сам токен, а не состояние пользователя, и переименование адреса
в базе не доезжало бы до клиента до перевыпуска токена.

### Guard для закрытых маршрутов

`src/modules/auth.ts` экспортирует не только роуты, но и плагин `authenticated`.
Закрыть новый модуль — это одна строка `.use(authenticated)`, после неё в
контексте появляется `userId`, а запрос без годного токена до обработчика не
доходит. Смотри `src/modules/meetings.ts` как образец.

- **`as: 'scoped'` у `resolve` обязателен.** Без него проверка и `userId`
  останутся внутри самого плагина, подключивший модуль их не увидит — и роут
  тихо станет открытым, а не сломается заметно.
- **Плагин `jwt` создаётся один раз** (`jwtPlugin`) и подключается и в выдачу
  токенов, и в guard. Elysia дедуплицирует плагины по имени, так что секрет и
  срок жизни не разъедутся между `sign` и `verify`.
- **`jwt.verify` возвращает `false` на любую негодность разом** — чужая подпись,
  битый формат, истёкший `exp`. Отдельно их не разбираем: клиенту во всех случаях
  один и тот же 401.
- **Токен без `sub` — тоже 401.** Подпись у него наша, но пользователя по нему не
  найти, и без явной проверки `userId` уехал бы в запрос как `undefined`.

### Встречи

`src/modules/meetings.ts`. Неочевидное:

- **Владелец подставляется в `where`, а не проверяется после выборки.** Чужая
  встреча не находится вовсе, и `GET /meetings/:id` отвечает на неё тем же 404,
  что и на несуществующий id. 403 подтвердил бы, что такая встреча есть.
- **`participants` — массив адресов, а не связь с `users`.** Приглашать можно и
  тех, кто ещё не зарегистрирован. Адреса приводятся к нижнему регистру и
  дедуплицируются — тем же правилом, что и e-mail в `users`.
- **Даты наружу уходят строго `toISOString()`.** На вход принимается любой
  корректный ISO-8601 (в том числе со смещением `+03:00`), в ответе — всегда UTC
  с миллисекундами; клиенту не приходится гадать, в каком виде вернётся дата.
- **Список отсортирован по `date` по возрастанию** — ближайшие первыми; под это
  заведён составной индекс `(owner_id, date)`.

### Файлы встречи

`src/modules/files.ts`, два маршрута: приём файла и список. Отдача, удаление и
лимиты — фазы 2–4 плана, их ещё нет: сейчас api принимает любой формат и любой
размер. Перед правкой — ресерч, см. раздел выше.

- **Тело запроса не парсится (`parse: 'none'`) и уходит на диск потоком.**
  `request.formData()` в Bun собирает файл в память целиком, а лимит на запись —
  2 ГБ. С `parse: 'none'` `request.body` остаётся нетронутым `ReadableStream`,
  который обработчик сливает в `Bun.file(...).writer()` сам.
- **`await` у каждой `writer.write()` — это и есть «потоком, а не в память».**
  `write()` возвращает промис, когда запись отложена; без ожидания цикл читает
  сокет быстрее, чем пишет диск, и буфер растёт до размера файла. Замер на 1 ГБ:
  +6 МБ RSS с `await` против +2423 МБ без него. Ни типы, ни тесты на мелких
  файлах этого не ловят — отсюда комментарий прямо у строки.
- **Имя и тип приходят заголовками, и имя обязано быть percent-encoded.**
  Значение HTTP-заголовка — байты Latin-1: `new Headers({ 'x-file-name':
'Отчёт.pdf' })` бросает исключение и в браузере, и в Bun. Контракт —
  `encodeURIComponent` на клиенте, `decodeURIComponent` здесь; битая строка
  (`%zz`) — это 400, а не 500.
- **Путь на диске генерирует сервер целиком** — `<UPLOAD_DIR>/<id встречи>/<id
файла><расширение>`, где расширение проходит через узкий шаблон. Исходное имя
  живёт только в метаданных, поэтому `../` в имени никуда не уводит.
- **Файл публикуется переименованием `.part` после вставки строки в базу.** Пока
  он пишется, его имени нет ни в одной строке, и читатель недописанного не
  увидит; уборка после любого отказа — удаление одного `.part`. Обрыв соединения
  клиентом виден как `AbortError` из цикла чтения, отдельно слушать
  `request.signal` не нужно.
- **Размер хранится `BigInt`, а наружу уходит `Number`.** Максимум `Int` в
  Postgres — 2 147 483 647 байт, файл ровно на 2 ГиБ туда не влезает; но `BigInt`
  в ответе роняет сериализацию пятисоткой «JSON.stringify cannot serialize
  BigInt». Конвертация — на границе ответа, рядом с `toISOString()`.
- **Список сортируется по `(createdAt, id)`, а не по одному `createdAt`.**
  Точность колонки — миллисекунда, и две загрузки подряд в неё укладываются;
  вторым ключом идёт `id` (uuid v7, то есть тоже по времени), иначе порядок
  одинаковых меток не определён и тест на него мигает.

## Тесты

Раннер — встроенный `bun test`, без Vitest и без Jest.

```
tests/setup.ts          preload: фиксирует окружение до импорта приложения
tests/helpers/http.ts   обёртка над app.handle
tests/helpers/jwt.ts    разбор и проверка подписи JWT без зависимостей
tests/*.e2e.test.ts     контракты маршрутов
```

E2E здесь — это `app.handle(new Request(...))`, а не запросы на порт. Через
`handle` проходит весь конвейер (CORS, валидация схем, обработка ошибок,
сериализация), но сервер не поднимается: тесты не дерутся за порт 3000 с
запущенным `bun run dev`.

Три вещи, которые важно не сломать:

- **`tests/setup.ts` подключён как `preload` в `bunfig.toml`, и порядок тут
  критичен.** `src/config/env.ts` читает `Bun.env` один раз, на загрузке модуля;
  если выставлять переменные внутри теста, приложение успеет импортироваться со
  старыми значениями. Всё, что тесту нужно от окружения, задаётся в `setup.ts`.
- **Тесты ходят в настоящую базу** (`bun run db:up` плюс накатанная схема,
  `bun run db:migrate`), моков нет — иначе «регистрация создаёт пользователя,
  логин ищет существующего» не проверить. Данные между прогонами не чистятся,
  поэтому e-mail'ы генерируются уникальными (`e2e-${randomUUID()}@example.com`);
  фикстуры с постоянными адресами упадут на втором запуске.
- **JWT в тестах разбирается вручную** (`tests/helpers/jwt.ts`, `node:crypto`), а
  не библиотекой, которой он выпущен. Иначе тест проверял бы сам себя: контракт
  здесь — формат RFC 7519 и подпись HS256 секретом из `JWT_SECRET`, а не выбор
  библиотеки.

`bun run check` тесты не запускает — гейт не должен требовать Docker.

## Ловушки, на которые уже наступали

**`.get('', ...)`, а не `.get('/', ...)` при заданном `prefix`.** Оба варианта
отвечают на `/health`, но со слэшем в OpenAPI-спеку попадает путь `/health/` — с
лишним хвостом. Смотри `src/modules/health.ts` как образец.

**Плагин `@elysiajs/swagger` мёртв** — застыл на 1.3.1 и не поддерживает Elysia 1.4.
Актуальная замена, которая здесь и стоит, — `@elysiajs/openapi`.

**Порядок плагинов значим.** `cors` подключается первым, до роутов, иначе часть
ответов уедет без CORS-заголовков.

**`toMatchObject` в `bun test` подменяет совпавшие поля матчером прямо в
проверяемом объекте.** После
`expect(body).toMatchObject({ token: expect.any(String) })` в `body.token` лежит
не строка, а `Any<String>`, и следующая же строка теста падает с
`token.split is not a function`. Поэтому в `tests/` асимметричных матчеров нет:
тип проверяется через `expect(typeof value).toBe('string')`.

## Схемы ответов кормят документацию

`@elysiajs/openapi` строит спеку из typebox-схем, а не из типов TypeScript. Роут без
`response`-схемы попадёт в `/docs` пустой заглушкой. Поэтому у новых роутов задавай
`response` через `t` и короткий `detail.summary`:

```ts
.get('', handler, {
  detail: { summary: 'Liveness probe' },
  response: t.Object({ status: t.Literal('ok') }),
})
```

Scalar UI — на `/docs`, сырая спека — на `/docs/json`. В production и то и другое
отключено через `enabled: !isProduction`.

Маршрут под `authenticated` дополнительно помечается `detail.security`
(`[{ bearerAuth: [] }]`) — сама схема `bearerAuth` объявлена в `app.ts`. Без этой
пометки в Scalar не будет поля для токена, и роут будет выглядеть открытым. Код
401 стоит держать в `response`-карте таких роутов: это и документация, и разрешение
Elysia отдать такой ответ из guard'а.

## Окружение

Читается только в `src/config/env.ts`, через `Bun.env`, и раздаётся дальше как
готовый объект `env`. Не тяни `Bun.env` напрямую в модули.

`CORS_ORIGINS` — список origin'ов через запятую, парсится там же. Новый разрешённый
адрес добавляется переменной окружения, не хардкодом в `app.ts`. Дефолт —
`http://localhost:5173`, то есть dev-сервер Nuxt; он должен совпадать с
`devServer.port` во фронтенде.

| Переменная              | Дефолт                  | Кто читает                                   |
| ----------------------- | ----------------------- | -------------------------------------------- |
| `PORT`, `HOST`          | `3000`, `0.0.0.0`       | `src/index.ts`                               |
| `CORS_ORIGINS`          | `http://localhost:5173` | `app.ts` через `env.corsOrigins`             |
| `DATABASE_URL`          | нет                     | `src/db/prisma.ts` и Prisma CLI              |
| `JWT_SECRET`            | нет                     | `src/modules/auth.ts`                        |
| `JWT_EXPIRES_IN`        | `7d`                    | там же, формат jose: `15m`, `7d`             |
| `UPLOAD_DIR`            | `./.uploads`            | `src/modules/files.ts` через `env.uploadDir` |
| `MAX_REQUEST_BODY_SIZE` | 2 ГиБ + 64 МБ           | `src/index.ts` → `app.listen`                |

**У `DATABASE_URL` и `JWT_SECRET` дефолта нет намеренно.** `env.ts` бросает
исключение на старте, если их не задали. Дефолт у секрета подписи — это дыра,
которая тихо доезжает до production и там выглядит как рабочая конфигурация;
падение при старте заметно сразу.

**А у `UPLOAD_DIR` дефолт есть, и это не непоследовательность.** Отсутствие
каталога загрузок дыры не создаёт, в отличие от предсказуемого секрета подписи, а
падение api при старте на свежем клоне — лишнее трение. Относительный путь
`env.ts` разворачивает в абсолютный сразу: рабочий каталог у `bun run dev:api` и
у `bun test` разный, и относительный уехал бы следом за ним.

**`MAX_REQUEST_BODY_SIZE` — это потолок Bun.serve, а не наш лимит.** Сверх него
Bun закрывает сокет молча, без ответа, так что в браузере превышение выглядит как
пропавшая сеть, а не как отказ api. Поэтому значение держится заведомо выше
лимита записи (2 ГиБ), чтобы первым срабатывал наш собственный ответ. Через
`app.handle` эта настройка не действует вовсе — тесты её не покрывают, проверять
только на запущенном сервере.

В тестах `JWT_SECRET` подменяется в `tests/setup.ts`, чтобы прогон не зависел от
локального `.env`; `DATABASE_URL` берётся из `.env` как есть — тестам нужна
настоящая база. `UPLOAD_DIR` там же переводится на временный каталог, который
убирается после прогона: писать загрузки в рабочий каталог тесты не должны.

## Документация

Полная таблица «что чем тянется» — в корневом `CLAUDE.md`, раздел «Документация
обновляется в том же коммите». Для бэкенда чаще всего срабатывает такое:

- **новый модуль в `src/modules/`** — если он вводит неочевидное правило, опиши его
  здесь; рутинный CRUD-модуль документировать не нужно, он читается из кода;
- **новый плагин Elysia** — сюда и в раздел «Тулинг» в `README.md`, с указанием,
  почему выбран именно он (как это сделано для `@elysiajs/openapi` против мёртвого
  `@elysiajs/swagger`);
- **новая переменная окружения** — `.env.example` и таблица в разделе «Окружение»;
- **правка `prisma/schema.prisma`** — миграция в том же коммите; новая таблица —
  ещё и раздел «База данных» в `README.md`;
- **смена порта или CORS-политики** — ещё и корневой `CLAUDE.md`, там описана
  связка порта фронтенда с `CORS_ORIGINS`;
- **новая ловушка**, на поиск которой ушло время — в «Ловушки, на которые уже
  наступали», обязательно с причиной, а не только с рецептом.
