# План: Загрузка файлов встречи

**PRD**: `docs/prd-meeting-file-upload.md`

**Дата**: 2026-09-12

## Развилки, закрытые до плана

PRD оставлял три места с несколькими прочтениями; решения приняты и зашиты в фазы:

- **Доступ к файлу без заголовка `Authorization`** — подписанный токен в query.
  `GET /meetings/:id/files` отдаёт у каждого файла готовое поле `url` со сроком
  15 минут; отдельного роута выдачи ссылки нет, операций api остаётся четыре.
  Плата: ссылка стареет, пока страница открыта, — на отказ плеера страница
  перезапрашивает список.
- **Транспорт загрузки** — сырое тело запроса потоком, имя и тип в заголовках.
  `request.formData()` в Bun собирает файл целиком в память, а PRD это прямо
  запрещает; готового потокового разбора multipart в Bun нет.
- **Сколько файлов за раз** — один. Выбор или дроп нескольких берёт первый и
  сообщает об этом; очередь в этой итерации не заводится.

Ещё одно место PRD не покрывает, и оно решено допущением: критерий «удаление
встречи удаляет её файлы с диска» есть, а роута `DELETE /meetings/:id` в api нет
и PRD его не вводит. Уборка каталога выносится функцией (фаза 4) и покрывается
тестом напрямую; роут удаления встречи — отдельная фича, и когда он появится, он
обязан эту функцию звать.

## Фазы реализации

### Фаза 1: Файл доезжает от браузера до диска

**Цель**: сквозной путь целиком, пусть и урезанный — со страницы встречи файл
уходит на api, пишется на диск потоком и возвращается в списке. Без лимитов,
прогресса, плеера и удаления.

**Затрагивает**: база данных, backend, frontend

**Задачи**:

- [ ] Модель `MeetingFile` в `prisma/schema.prisma`: исходное имя, размер
      (`BigInt` — 2 ГБ не влезают в 32-битный `Int`), MIME-тип, группа
      (`FileKind`), статус (`FileStatus`: `uploaded`, `processing`, `ready`,
      `failed`), относительный путь, `meetingId` с `onDelete: Cascade`, индекс
      `(meeting_id, created_at)`; миграция `bun run db:migrate` в том же коммите.
      Туда же `UPLOAD_DIR` в `src/config/env.ts`, `apps/api/.env.example`,
      таблица окружения в `apps/api/CLAUDE.md` и каталог в `.gitignore`.
- [ ] `POST /meetings/:id/files` — новый модуль `src/modules/files.ts` под
      `.use(authenticated)`, подключённый в `app.ts`: тело не парсится
      (`parse: 'none'`), поток пишется через `Bun.file(dest).writer()`, имя и тип
      приходят заголовками, путь на диске генерирует сервер
      (`<UPLOAD_DIR>/<meetingId>/<fileId><ext>`) — исходное имя живёт только в
      метаданных. Ответ 201 с метаданными, чужая встреча — 404, без токена — 401.
- [ ] `GET /meetings/:id/files` — имя, размер, MIME-тип, группа, статус и
      `createdAt` в ISO-8601 UTC, сортировка по дате загрузки. Размер наружу
      уходит числом: `BigInt` не сериализуется в JSON и роняет ответ.
- [ ] Страница `apps/web/app/pages/meetings/[id].vue`: карточка встречи из
      `GET /meetings/:id`, блок «Файлы» со списком, кнопка выбора файла и
      композабл `useMeetingFiles`. Плюс `routeRules` для `/meetings/**`
      (`ssr: false` и `X-Robots-Tag`), ссылка со строки дашборда (`MeetingItem`)
      и обработка 401 как в кабинете: `isUnauthorized` → `logout()` → `/login`.
- [ ] `apps/api/tests/files.e2e.test.ts`: загрузка документа с метаданными,
      список, чужая встреча 404, обе операции без токена 401. `UPLOAD_DIR`
      перекрывается временным каталогом в `tests/setup.ts` (до импорта
      приложения — `env.ts` читает `Bun.env` один раз) и убирается после прогона.

**Когда готова**: на `/meetings/{id}` выбран документ 5 МБ — api ответил 201,
файл лежит в `UPLOAD_DIR/<id встречи>/`, после перезагрузки страницы он в списке
с размером и датой; загрузка записи 1 ГБ проходит, и RSS процесса api за время
загрузки вырастает не больше чем на 200 МБ (замер до и после); `bun run test`
зелёный.

### Фаза 2: Лимиты и форматы на api

**Цель**: api сам отбивает всё, что принимать не должен, и не оставляет на диске
недописанных файлов.

**Затрагивает**: backend

**Задачи**:

- [ ] Одно место с ограничениями (`src/modules/files/limits.ts`): две группы
      форматов (расширение плюс допустимые MIME-типы), 2 ГБ на запись, 50 МБ на
      документ, 20 файлов на встречу. Оттуда их читают и обработчик, и тесты.
- [ ] 415 на расширение или заявленный тип вне обоих списков — до того, как файл
      открыт на запись.
- [ ] 413 по `Content-Length` и повторно по факту записанных байт: клиент может
      соврать в заголовке, поэтому счётчик в потоке обязателен. На превышении
      поток обрывается, недописанный файл удаляется.
- [ ] 409 с русским текстом про лимит на 21-й файл встречи; счёт и вставка — в
      одной транзакции, иначе два параллельных запроса пролезут на 21-е место.
- [ ] Тесты: 413 для записи больше 2 ГБ и документа больше 50 МБ (бьём по
      `Content-Length`, а не гоним гигабайты через `app.handle`), 415 на `.zip`,
      409 на 21-й файл, имя `../../etc/passwd`; после каждого отказа каталог
      встречи пуст.

**Когда готова**: `.zip` → 415; документ 51 МБ и запись с заявленными 2.1 ГБ →
413, в `UPLOAD_DIR` ничего не появилось; 21-й файл → 409 с текстом про лимит;
файл с именем `../../etc/passwd` лежит внутри `UPLOAD_DIR`, а в списке
показывается исходным именем.

### Фаза 3: Отдача файла: ссылка, `Range`, имя

**Цель**: браузер может проиграть запись и скачать документ, не имея возможности
послать заголовок `Authorization`.

**Затрагивает**: backend

**Задачи**:

- [ ] Подписанный токен доступа к файлу: HS256 тем же `JWT_SECRET`, но со своим
      `typ: 'file'` и `sub: <id файла>` — сессионный токен не должен открывать
      файл, а файловый не должен открывать `/auth/me`. Срок из
      `FILE_LINK_EXPIRES_IN` (дефолт `15m`) — переменная в `.env.example` и в
      таблице окружения `apps/api/CLAUDE.md`.
- [ ] Поле `url` у каждого файла в `GET /meetings/:id/files` — ссылка на отдачу с
      `?token=`, выписанная в момент запроса списка.
- [ ] `GET /meetings/:id/files/:fileId/content`: токен из query (401 на
      просроченный, чужой и сессионный), 404 на чужую встречу, тело — поток
      `Bun.file(path)` без чтения в память, `Content-Type` из метаданных,
      `Content-Disposition` с кодировкой имени по RFC 5987 — иначе кириллица и
      пробелы в имени приезжают битыми.
- [ ] `Range`: `Accept-Ranges: bytes` всегда, 206 с `Content-Range` и куском на
      запрос с диапазоном, 200 и файл целиком без заголовка, 416 на диапазон за
      пределами файла.
- [ ] Тесты: 200 без `Range` и совпадение длины с размером, 206 с точным куском,
      истёкший токен → 401, сессионный токен вместо файлового → 401, чужая
      встреча → 404, `Content-Disposition` с кириллическим именем.

**Когда готова**: запрос по ссылке из списка с `Range: bytes=0-99` отвечает 206 и
ровно 100 байт, без заголовка — 200 и файл целиком; ссылка с `exp` в прошлом —
401; `bun run test` зелёный.

### Фаза 4: Удаление файла и уборка за встречей

**Цель**: файл исчезает из базы, с диска и по ранее выданной ссылке; удаление
встречи не оставляет каталогов-сирот.

**Затрагивает**: backend

**Задачи**:

- [ ] `DELETE /meetings/:id/files/:fileId`: 204 в успехе, запись из базы и файл с
      диска, 404 на чужую встречу и на уже удалённый файл, 401 без токена.
- [ ] Отдача проверяет существование записи до чтения с диска: у ранее выданной
      ссылки `exp` ещё годен, но файла больше нет — ответ 404.
- [ ] `removeMeetingFiles(meetingId)` в `src/modules/files/storage.ts` — удаление
      каталога встречи целиком. Роута удаления встречи PRD не вводит, поэтому
      функция пока вызывается только из тестов; появится `DELETE /meetings/:id` —
      он обязан её звать, иначе каталоги остаются на диске навсегда.
- [ ] Тесты: после удаления повторный список файла не содержит, файла на диске
      нет, ранее выданная ссылка отвечает 404; `prisma.meeting.delete` плюс
      `removeMeetingFiles` не оставляет каталога встречи в `UPLOAD_DIR`.

**Когда готова**: удалённый файл отсутствует и в списке, и в `UPLOAD_DIR`, его
старая ссылка отвечает 404; каталог удалённой встречи с диска убран;
`bun run test` зелёный, все четыре операции отвечают 401 без токена и 404 на
чужую встречу.

### Фаза 5: Загрузка в интерфейсе: прогресс, отмена, проверка до отправки

**Цель**: пользователь видит, что происходит с его файлом, и может остановить
загрузку; заведомо негодный файл не уезжает на api вовсе.

**Затрагивает**: frontend

**Задачи**:

- [ ] `apps/web/app/utils/files.ts`: списки расширений и границы размера — копия
      контракта api, с тем же предупреждением в комментарии, что и у границ
      `credentials`: разъезд не поймают ни типы, ни сборка. Там же русские тексты
      отказов («Файл больше 2 ГБ», «Формат .zip не поддерживается»).
- [ ] Проверка выбранного файла до отправки: на отказе показывается причина и не
      уходит ни одного сетевого запроса.
- [ ] Отправка через `XMLHttpRequest` в `useMeetingFiles`: `$fetch` не сообщает о
      переданных байтах, а без них процент показать нечем; `upload.onprogress`
      даёт прогресс, `abort()` — отмену, которая доходит до api и убирает
      недописанный файл.
- [ ] Кнопка выбора и зона перетаскивания: один файл за раз, дроп нескольких
      берёт первый и говорит об этом; во время загрузки видны имя файла, процент
      и кнопка «Отменить».
- [ ] Прогон в браузере (Playwright MCP): загрузка файла ~200 МБ с растущим
      процентом, отмена на середине, выбор `.zip` и файла больше лимита с
      проверкой лога сетевых запросов.

**Когда готова**: во время загрузки на странице видны имя файла, процент и
«Отменить»; отмена на середине убирает строку, файл в списке не появляется и в
`UPLOAD_DIR` не остаётся; выбор `.zip` и файла больше лимита даёт русский текст
отказа, а в логе запросов Playwright запроса к api нет.

### Фаза 6: Просмотр: плеер, скачивание, удаление

**Цель**: загруженное можно посмотреть, скачать и убрать, не выходя со страницы
встречи.

**Затрагивает**: frontend

**Задачи**:

- [ ] Строка файла: иконка и подпись по группе (`i-lucide-video`,
      `i-lucide-music`, `i-lucide-file-text`), размер, дата; у записи
      дополнительно статус «Загружена, обработка не запускалась».
- [ ] Плеер разворачивается только у записей: `<video controls>` или
      `<audio controls>` с `src` из поля `url`, `aria-label` с именем файла.
      Отказ плеера (ссылка протухла) перезапрашивает список и берёт свежий `url`.
- [ ] Скачивание документа ссылкой на `url`: атрибут `download` на кросс-origin
      ссылке браузер игнорирует, поэтому имя приезжает только из
      `Content-Disposition` api — проверять надо именно результат скачивания.
- [ ] Удаление файла с подтверждением (`UModal`), после успеха строка пропадает
      из списка без перезагрузки страницы.
- [ ] Прогон в браузере: mp4 играет и перематывается (снапшот дерева доступности
      — у элементов управления есть имена), документ с кириллицей и пробелами в
      имени скачивается под исходным именем, удаление подтверждается.

**Когда готова**: загруженный mp4 воспроизводится на `/meetings/{id}` и
перематывается кликом по дорожке; документ с именем вида «Отчёт за квартал.pdf»
скачивается под этим же именем; удалённый файл пропадает из списка сразу после
подтверждения.

### Фаза 7: Состояния блока, доступность и сопровождение

**Цель**: блок «Файлы» ведёт себя предсказуемо не только в успешном сценарии, а
документация не расходится с тем, что получилось.

**Затрагивает**: frontend, документация

**Задачи**:

- [ ] Состояния блока: пустое (пояснение и кнопка загрузки, а не пустое место),
      загрузка данных (один `role="status"` со своим текстом, скелетоны под
      `aria-hidden` — иначе каждый `USkeleton` объявляет своё «loading»), отказ
      api (русский текст в `role="alert"` с кнопкой «Повторить»), при появлении
      сообщения соседние элементы не сдвигаются.
- [ ] Прогон Playwright MCP по чек-листу из `apps/web/CLAUDE.md`: снапшот дерева
      доступности, обе темы, 360px и десктоп, `scrollWidth === clientWidth`, цели
      нажатия ≥ 24×24px, контраст текста ≥ 4.5:1 и рамок с иконками ≥ 3:1 (замер
      через `<canvas>`, а не разбором `getComputedStyle` — Tailwind 4 отдаёт
      `oklch`), 401 на странице гасит сессию и уводит на `/login`.
- [ ] Правки по найденным замерам и запись найденного в разделы «Что проверено в
      браузере» и «Ловушки» в `apps/web/CLAUDE.md`.
- [ ] Документация: таблица маршрутов и раздел про загрузку в
      `apps/web/CLAUDE.md`, таблица маршрутов в `apps/api/CLAUDE.md`, разделы
      «База данных» и «Переменные окружения» в `README.md` — включая то, что
      часть состояния теперь лежит на диске мимо compose и дамп базы без каталога
      файлов бесполезен.
- [ ] `bun run check` и `bun run test` при поднятом Postgres.

**Когда готова**: на 360px и на десктопе в обеих темах горизонтального скролла
нет, все замеры из чек-листа в норме, пустой блок и отказ api показывают текст, а
не пустое место; `bun run check` и `bun run test` зелёные; ни один файл
документации не описывает загрузку иначе, чем она работает.

## Заметки для прогона

- Встречу для проверок заводить из браузера — форма Scalar на `/docs`, — а не
  seed-скриптом: скрипт заводит данные мимо тех путей, которыми пользуется
  пользователь.
- Кириллические имена файлов не проверять через `curl -d` в Git Bash: payload
  уезжает не в UTF-8, и в базу попадают `U+FFFD` — дефект выглядит как ошибка
  api, хотя его там нет. Такой файл загружать из браузера.
- Тесты api ходят в настоящую базу, поэтому перед прогоном — `bun run db:up` и
  `bun run db:migrate`; pre-commit-хук требует того же.
