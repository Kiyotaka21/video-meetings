# PRD: Загрузка файлов встречи

**Дата**: 2026-09-12

**Статус**: Draft

## Цель

Владелец встречи прикладывает к ней файлы — готовую запись (аудио или видео) и
сопутствующие документы, — и они хранятся вместе со встречей, а не в личной
папке на диске. В этой итерации закрывается загрузка, хранение и просмотр
файлов внутри встречи; сама обработка (транскрибация, конспект) сюда не входит,
но модель данных и статусы заводятся так, чтобы её можно было добавить
следующей фичей без миграции UI.

## Пользовательские сценарии

- Пользователь кликает встречу в списке на дашборде -> попадает на страницу
  встречи `/meetings/{id}` с названием, датой, участниками и блоком «Файлы».
- Пользователь выбирает файл через кнопку или перетаскивает его в блок
  «Файлы» -> видит имя файла, размер и прогресс загрузки в процентах.
- Загрузка завершилась -> файл появляется в списке с именем, размером, датой
  загрузки и иконкой по типу; у записи дополнительно виден статус «Загружена,
  обработка не запускалась».
- Пользователь нажимает «Отменить» во время загрузки -> передача
  прекращается, файл в списке не появляется, недописанный файл на диске не
  остаётся.
- Пользователь выбирает файл неподдерживаемого формата или больше лимита ->
  получает отказ с понятной причиной до того, как началась передача байтов.
- Пользователь открывает загруженную запись -> она воспроизводится прямо на
  странице (встроенный плеер) с возможностью перемотки.
- Пользователь открывает документ -> скачивает его по ссылке.
- Пользователь удаляет файл -> он пропадает из списка и с диска, ссылка на
  него перестаёт открываться.
- Пользователь открывает `/meetings/{id}` чужой встречи -> страница сообщает,
  что встреча не найдена (api отвечает 404, не подтверждая её существование).
- У пользователя истекла сессия -> api отвечает 401, страница гасит сессию и
  уводит на `/login` — так же, как дашборд.

## В скоупе

**Хранение**

- Одна встреча хранит до 20 файлов.
- Принимаются две группы форматов:
  - записи встречи: видео `mp4`, `webm`, `mov`, аудио `mp3`, `m4a`, `wav`,
    `ogg` — до 2 ГБ на файл;
  - документы: `pdf`, `docx`, `pptx`, `xlsx`, `txt`, `md`, `csv` — до 50 МБ
    на файл.
- Всё, что не входит в список, api отклоняет.
- У файла хранятся: исходное имя, размер, MIME-тип, группа (запись или
  документ), дата загрузки, статус и ссылка на встречу.
- Статус — перечисление с местом под будущую обработку: `uploaded`,
  `processing`, `ready`, `failed`. В этой итерации файл всегда остаётся в
  `uploaded`, остальные значения никто не выставляет. К документам обработка не
  относится вовсе, статус у них технический.
- Файл лежит на диске в каталоге вне репозитория, в базе — только метаданные и
  относительный путь.
- Удаление встречи удаляет её файлы и с диска тоже.

**API**

- Загрузка файла в конкретную встречу, список файлов встречи, скачивание или
  отдача файла для плеера, удаление файла.
- Все четыре операции доступны только владельцу встречи; для чужой встречи
  ответ неотличим от несуществующей.
- Валидация размера и формата на стороне api обязательна и не полагается на
  проверку в браузере.
- Отдача файла поддерживает перемотку видео и аудио, а не только скачивание
  целиком.

**Интерфейс**

- Новая страница `/meetings/{id}`: карточка встречи (название, дата,
  участники) и блок «Файлы».
- Строка встречи на дашборде ведёт на страницу встречи.
- Блок «Файлы»: список файлов, кнопка загрузки, зона перетаскивания, пустое
  состояние, состояние загрузки данных, состояние отказа api.
- Записи и документы в одном списке, различаются иконкой и подписью типа;
  плеер разворачивается только у записей.
- Во время загрузки: имя файла, прогресс в процентах, кнопка отмены.
- Проверка формата и размера до отправки — чтобы не гнать 2 ГБ ради отказа.
- Ошибки формулируются по-русски и объясняют причину отказа («Файл больше
  2 ГБ», «Формат .zip не поддерживается»), а не показывают код ответа.
- Удаление файла с подтверждением.

## Не в скоупе

- Любая фактическая обработка: транскрибация, конспект, поиск по записи,
  определение говорящих. Заводятся только статусы под неё.
- Просмотр документов внутри приложения: PDF и офисные форматы скачиваются, а
  не открываются во встроенном вьюере.
- Запись встречи прямо из браузера — файл приносит пользователь.
- Извлечение длительности, постеров-превью, перекодирование, проверка кодеков.
- Возобновляемая загрузка и докачка после обрыва связи: прерванная загрузка
  начинается заново.
- Доступ к файлам для участников встречи — сейчас участники это адреса, а не
  пользователи; файлы видит только владелец.
- Публичные ссылки на файл, доступ по ссылке без входа.
- Квоты на пользователя, антивирусная проверка, корзина и восстановление
  удалённых файлов.
- Редактирование встречи и переименование файлов.

## Технические ограничения

- **Файлы лежат на локальном диске api**, каталог задаётся переменной
  окружения, в репозиторий не попадает (`.gitignore`) и в образ не
  упаковывается. Новых сервисов в `docker-compose.yml` не появляется.
- **Состояние теперь в двух местах.** Postgres живёт в compose, файлы — на
  диске хоста: дамп базы без каталога файлов бесполезен, переезд на другую
  машину переносит оба. Это плата за отказ от объектного хранилища, и её нужно
  зафиксировать в `README.md`.
- **Имя файла от пользователя не участвует в пути на диске.** Путь целиком
  генерирует сервер, исходное имя остаётся только в метаданных — иначе
  `../` в имени уводит запись за пределы каталога.
- **Файл до 2 ГБ нельзя буферизовать в памяти** — ни при приёме, ни при
  отдаче. Запись на диск и чтение с него идут потоком.
- **Отдача видео требует поддержки `Range`**, иначе плеер не перематывает и на
  части браузеров вообще не начинает воспроизведение. С объектным хранилищем
  это досталось бы даром, со своей отдачей — отдельная работа.
- **Тег `<video>` не умеет слать заголовок `Authorization`.** Значит, ссылка на
  файл для плеера должна нести собственный короткоживущий признак доступа;
  просто «дёрнуть тот же роут с токеном в заголовке» не выйдет.
- **Срок жизни такой ссылки — минуты, а не часы.** Она утекает вместе с
  историей браузера и логами прокси.
- **Прогресс загрузки не виден через `$fetch`**: ему нужен способ отправки,
  который сообщает о переданных байтах, иначе процент показать нечем.
- **Отмена должна доходить до диска.** Прерванный запрос без уборки оставляет
  недописанный файл, за который никто не отвечает.
- **`Content-Type` от клиента не доверенный.** Проверяются расширение и
  заявленный тип; разбор сигнатуры файла в этой итерации не делается — это
  осознанная дыра, а не упущение.
- **Лимиты дублируются на клиенте.** Как со схемой `credentials`: границы
  размера и списки форматов лежат и на api, и в утилитах `web`, разъезд не
  ловится ни типами, ни сборкой.
- **Тестам api по-прежнему хватает Postgres** — pre-commit-хук не меняется, но
  тесты загрузки должны писать во временный каталог, а не в рабочий, и убирать
  за собой.
- **CORS**: загрузка идёт с того же origin'а фронтенда (`5173` по умолчанию),
  список в `CORS_ORIGINS` не меняется, но проверяется на preflight с
  заголовками загрузки.

## Критерии готовности

**API**

- [ ] Загрузка записи 1 ГБ поддерживаемого формата отвечает `201` с
      метаданными файла, файл лежит на диске, потребление памяти процессом api
      за время загрузки не растёт пропорционально размеру файла.
- [ ] Запись больше 2 ГБ и документ больше 50 МБ отклоняются с `413`, файл на
      диске не создаётся.
- [ ] Файл формата вне обоих списков (например `.zip`, `.exe`) отклоняется с
      `415`.
- [ ] Двадцать первый файл во встрече отклоняется с `409` и текстом про лимит.
- [ ] Имя файла вида `../../etc/passwd` сохраняется как метаданные, а файл
      оказывается внутри каталога загрузок.
- [ ] Запрос без токена или с негодным токеном — `401` на всех четырёх
      операциях.
- [ ] Любая операция с файлом чужой встречи — `404`, тело ответа не отличает
      «чужая» от «не существует».
- [ ] Список файлов встречи отдаёт имя, размер, MIME-тип, группу, статус и
      дату загрузки; даты — ISO-8601 в UTC, как у `/meetings`.
- [ ] Запрос с заголовком `Range` отвечает `206` и запрошенным куском файла,
      без него — `200` и файл целиком.
- [ ] Ссылка на файл перестаёт открываться позже 15 минут после выдачи.
- [ ] Удаление файла: повторный список его не содержит, файла на диске нет,
      ранее выданная ссылка отвечает отказом.
- [ ] Удаление встречи удаляет её файлы с диска.
- [ ] e2e-тесты в `apps/api/tests` покрывают: успешную загрузку записи и
      документа, превышение размера для обеих групп, неподдерживаемый формат,
      лимит на количество, имя с `../`, чужую встречу, `401`, `Range`,
      удаление.

**Интерфейс**

- [ ] Клик по встрече на дашборде открывает `/meetings/{id}` с названием,
      датой и участниками той же встречи.
- [ ] Пустой блок «Файлы» показывает пояснение и кнопку загрузки, а не пустое
      место.
- [ ] Во время загрузки видны имя файла, процент и кнопка отмены; отмена
      останавливает запрос и не оставляет файла в списке.
- [ ] Выбор файла неподдерживаемого формата или больше лимита показывает
      причину отказа без сетевого запроса (в логе запросов Playwright запроса
      нет).
- [ ] Отказ api выводится текстом на русском в элементе с `role="alert"`,
      соседние элементы не сдвигаются (0px по `getBoundingClientRect()`).
- [ ] Загруженные видео и аудио воспроизводятся на странице и перематываются;
      у плеера есть доступные подписи элементов управления.
- [ ] Документ скачивается под исходным именем, включая имя с кириллицей и
      пробелами.
- [ ] Ответ `401` на странице встречи гасит сессию и уводит на `/login`.
- [ ] Страница проверена Playwright MCP: снапшот дерева доступности снят, обе
      темы, ширины 360px и десктоп, горизонтального скролла нет
      (`scrollWidth === clientWidth`), цели нажатия ≥ 24×24px, контраст текста
      ≥ 4.5:1, рамок и иконок ≥ 3:1.

**Сопровождение**

- [ ] `bun run check` проходит, `bun run test` зелёный при поднятом Postgres.
- [ ] Миграция Prisma лежит в том же коммите, что и правка схемы.
- [ ] Обновлены: таблица маршрутов в `apps/api/CLAUDE.md`, таблица маршрутов и
      раздел загрузки в `apps/web/CLAUDE.md`, разделы «База данных» и
      «Переменные окружения» в `README.md` — включая то, что часть состояния
      теперь лежит на диске мимо compose, — и `apps/api/.env.example`.
