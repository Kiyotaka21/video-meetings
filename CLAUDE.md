# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Пояснения к отдельным воркспейсам — в `apps/web/CLAUDE.md` и `apps/api/CLAUDE.md`.

## Что это

Монорепозиторий на **Bun workspaces**: Nuxt-фронтенд и Elysia-бэкенд для сервиса
видеовстреч. Продукт на ранней стадии: в `api` есть регистрация с логином
(`/auth/register`, `/auth/login`) и встречи под авторизацией (`/meetings`),
фронтенд их ещё не использует.

| Воркспейс             | Путь       | Стек                        | Порт |
| --------------------- | ---------- | --------------------------- | ---- |
| `@video-meetings/web` | `apps/web` | Nuxt 4 (Vue 3, Vite, Nitro) | 5173 |
| `@video-meetings/api` | `apps/api` | Elysia.js на Bun, Prisma 7  | 3000 |

`packages/` заведён под общие библиотеки, но пуст. Состояние — Postgres 18 из
корневого `docker-compose.yml`; сами приложения в контейнерах не запускаются.

## Команды

Все команды запускаются из корня; в воркспейсы попадают через `bun run --filter`.

```bash
bun install               # postinstall в web сам выполнит nuxt prepare
bun run dev               # web (5173) + api (3000) параллельно
bun run dev:web           # по отдельности
bun run dev:api
bun run build             # оба приложения
bun run check             # format:check + lint + typecheck — общий гейт
bun run test              # bun test в apps/api; требует поднятой базы
bun run db:up             # Postgres в docker-compose, с ожиданием healthcheck
bun run db:down           # остановить (том с данными остаётся)
bun run db:logs           # docker compose logs -f postgres
bun run db:migrate        # prisma migrate dev — схема из apps/api/prisma
bun run db:generate       # prisma generate — пересобрать клиент
```

Точечно по одному воркспейсу — либо корневые алиасы (`dev:web`, `build:api`,
`start:web`, `start:api`), либо напрямую:

```bash
bun run --filter @video-meetings/api typecheck
cd apps/web && bun run dev
```

`lint` только проверяет, `lint:fix` правит — и в корне, и в воркспейсах.
Форматирует исключительно Prettier: `eslint-config-prettier` стоит последним в
цепочке и глушит стилевые правила ESLint, так что стиль в ESLint добавлять не нужно.

## Тесты

Раннер — встроенный `bun test`, и пока он настроен только в `api`
(`apps/api/tests/`, подробности — в `apps/api/CLAUDE.md`). Корневой
`bun run test` — алиас на этот воркспейс, а не на все сразу; для `web` тестов
нет, там понадобится `@nuxt/test-utils` с Vitest.

```bash
bun run db:up             # тесты api ходят в настоящую базу, моков нет
bun run db:migrate        # схема должна быть накатана, иначе тесты падают на SQL
bun run test              # = bun run --filter @video-meetings/api test
bun run --filter @video-meetings/api test:watch
```

`bun run check` тесты **не** запускает: гейт остаётся быстрым и не требует
Docker. В CI тесты — отдельный шаг после `check`.

Разработка идёт от тестов: сначала падающий тест на контракт, потом реализация.
Красные тесты в репозитории — нормальное промежуточное состояние, а не поломка.

## Как устроена связность

**ESLint — один flat-config на весь репозиторий** (`eslint.config.js` в корне).
Внутри он разделён на именованные блоки: общие правила, блок для `.vue`, блок для
`apps/web` (браузерные globals) и блок для `apps/api` (node + `Bun`). Не заводи
per-app конфиги — глобальный `bun run lint` рассчитан на то, что конфиг один.
Почему в блоке `app/web` выключены два правила — объяснено в `apps/web/CLAUDE.md`.

**Правки агента форматирует хук, а не человек.** `.claude/settings.json` вешает на
`PostToolUse` (matcher `Write|Edit|NotebookEdit`) скрипт
`.claude/hooks/format-file.mjs`, и Prettier проходит по каждому файлу, который
записал агент. Смысл — чтобы `bun run check` не падал на форматировании через
десяток правок. Правки, сделанные через Bash (`sed`, heredoc), хук не видит: там
путь к файлу в payload не приходит.

Три неочевидности внутри скрипта:

- Вход приходит JSON'ом на stdin, и разбирает его `bun`, а не `jq`: `jq` в
  окружении может не стоять, а `bun` тут обязателен и так.
- Запускается `node_modules/prettier/bin/prettier.cjs`, а не shim из
  `node_modules/.bin` — у bun на Windows это `.exe`, у npm `.cmd`, и звать их
  пришлось бы по-разному.
- Любая осечка — тихий выход с кодом 0, чтобы хук не ломал ход агента. Исключение
  одно: если Prettier не смог разобрать файл, текст ошибки уходит модели через
  `additionalContext` — это признак, что правка сломала синтаксис.

`.prettierignore` хук уважает (Prettier сам подхватывает его из cwd), поэтому
`.agents/` и `.claude/skills/` остаются нетронутыми. Сам скрипт живёт под линтом:
именованный блок `app/claude-hooks` в `eslint.config.js` выдаёт ему node-globals,
без них `eslint .` спотыкается на `process` и `Buffer`.

**Playwright MCP объявлен в `.mcp.json` и коммитится.** Корневой `.mcp.json` —
единственный MCP-сервер проекта: `playwright` (`npx @playwright/mcp@latest`,
транспорт stdio). Он даёт агенту настоящий браузер — открыть `http://localhost:5173`,
снять accessibility-снапшот страницы, покликать, прочитать консоль и сетевые
запросы. Осмысленно только при запущенном `bun run dev`: сервер сам ничего не
поднимает.

Пять неочевидностей:

- **Файл в репозитории ещё не значит «включено».** Серверы из `.mcp.json`
  Claude Code спрашивает у каждого пользователя при первом запуске и запоминает
  ответ в `~/.claude.json` (`enabledMcpjsonServers` для этого проекта). Пока не
  подтвердил — инструментов `mcp__playwright__*` в сессии не будет; проверить
  можно через `/mcp` или `claude mcp list`.
- **Local scope перекрывает проектный.** Если тот же сервер уже добавлен через
  `claude mcp add playwright` (scope `local`, тоже в `~/.claude.json`), работает
  локальная запись, а `.mcp.json` игнорируется. Правки в репозитории при этом
  выглядят «не применившимися» — снимается через
  `claude mcp remove playwright -s local`.
- **Команда — `npx`, хотя пакетный менеджер здесь Bun.** Так документирует сам
  сервер, и так проверено; `bunx` запускает пакет на рантайме Bun, а Playwright
  тянет собственный Node-драйвер, и это лишний риск ради нулевой выгоды.
- **Сервер пишет артефакты в рабочую папку.** Снапшоты, логи консоли и скриншоты
  уезжают в `.playwright-mcp/` рядом с кодом, поэтому каталог занесён и в
  `.gitignore`, и в `.prettierignore`: без второго `bun run check` падал бы на
  форматировании сгенерированных `.yml`.
- **Браузер живёт вне проекта.** Пакет `@playwright/mcp` в `package.json` не
  прописан (его тянет `npx`), а бинарники браузеров ставятся глобально:
  `npx playwright install chrome`. По умолчанию сервер берёт установленный Chrome
  — на машине без него первый вызов упадёт именно на этом.

**Postgres живёт в compose, приложения — нативно.** Корневой `docker-compose.yml`
поднимает единственный сервис `postgres` (образ `postgres:18-alpine`, контейнер
`video-meetings-postgres`). `web` и `api` в контейнеры не заворачивались: они
запускаются через `bun run dev`, а в Docker выносится только состояние.

Три неочевидности:

- **Том смонтирован на `/var/lib/postgresql`, а не на `/var/lib/postgresql/data`.**
  В образе 18-й версии `PGDATA` переехал в `/var/lib/postgresql/18/docker`, и
  `VOLUME` объявлен на родительский каталог. Со старым путём Docker создал бы
  рядом анонимный том, и данные исчезали бы при пересоздании контейнера.
- **Креды и порт читаются из корневого `.env`** — compose подхватывает `.env` из
  каталога, где лежит compose-файл, и это отдельный файл от `apps/*/.env`. Все
  переменные заданы через `${VAR:-default}`, поэтому без `.env` compose тоже
  работает; переопределять нужно только при конфликте, например когда порт 5432
  уже занят локально установленным Postgres (`POSTGRES_PORT`).
- **`db:up` идёт с `--wait`**, то есть возвращает управление только после
  healthcheck (`pg_isready`), а не сразу после `docker start`. Это нужно, чтобы
  скрипт можно было ставить перед миграциями или тестами, не подкладывая sleep.

**Строка подключения живёт в `apps/api/.env`, а не в корневом.** Корневой `.env`
читает только compose (`POSTGRES_*`), приложение его не видит. `DATABASE_URL` для
Prisma лежит в `apps/api/.env` и должен совпадать с кредами из compose; при смене
`POSTGRES_*` правятся оба файла. Схема, миграции и клиент — целиком в `api`,
подробности в `apps/api/CLAUDE.md`.

**Зависимости UI живут в `apps/web`, не в корне.** В корне только тулинг: ESLint,
Prettier, TypeScript. `@nuxt/ui` и `tailwindcss` относятся к фронтенду и стоят в
`apps/web/package.json` — если инструмент или скилл дописал их в корневой
`dependencies`, это ошибка размещения, переноси в воркспейс.

**Prettier знает про Tailwind.** `prettier-plugin-tailwindcss` сортирует классы, а
`tailwindStylesheet` в `.prettierrc.json` указывает на
`apps/web/app/assets/css/main.css`. Это единственная ссылка из корневого конфига
внутрь воркспейса — при переносе CSS-входа её надо править.

**TypeScript зафиксирован на `^5` намеренно.** Latest — 7.x, но `typescript-eslint`
и `vue-tsc` пока не принимают его в peer-диапазоне. `bun update` может незаметно
подтянуть 7.x и сломать линт с typecheck — если версия поехала, откатывай на `^5`,
а не правь конфиги под неё.

**Общие compilerOptions — в `tsconfig.base.json`,** его расширяют оба воркспейса.
Там включены `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters` и
`verbatimModuleSyntax`. Последнее вместе с правилом `consistent-type-imports`
означает inline-стиль импорта типов: `import { type Foo, bar } from './x'`.

**Порты связаны через CORS.** `devServer.port` у Nuxt (5173) должен совпадать с тем,
что лежит в `CORS_ORIGINS` у api (дефолт `http://localhost:5173`). Меняешь порт
фронтенда — правь и `apps/api/.env`, иначе браузер начнёт отбрасывать ответы.
`bun run dev` требует, чтобы оба порта были свободны.

**Контракт `/auth` продублирован на клиенте.** Форма регистрации не спрашивает у
api, какие данные он примет: границы адреса и пароля лежат в
`apps/web/app/utils/auth.ts` и повторяют схему `credentials` из
`apps/api/src/modules/auth.ts`. Разъезд не ловят ни типы, ни сборка — форма просто
начинает отправлять заведомо отказные запросы или отбивать годные. То же со сроком
сессии: `maxAge` куки `auth_token` в `apps/web/app/composables/useAuth.ts` держится
равным `JWT_EXPIRES_IN` из `apps/api/.env` (7 дней по умолчанию). Правишь схему или
срок на api — правь и клиент; подробности в `apps/web/CLAUDE.md`.

**`.gitattributes` держит LF в рабочей копии** (`* text=auto eol=lf`). У Prettier
`endOfLine: "lf"`, а git на Windows иначе конвертирует в CRLF — и `bun run check`
падал бы сразу после клона. Не удаляй эту строку.

**`.agents/` исключена из Prettier и ESLint** — там лежат установленные скиллы
агентов, сторонний контент, который не надо приводить к нашему стилю.

## Документация обновляется в том же коммите

Правка, меняющая архитектуру, считается незавершённой, пока документация ей
противоречит. Устаревшая дока хуже отсутствующей: следующий агент поверит ей и
станет действовать по несуществующим правилам.

Где что живёт — не дублируй один факт в двух местах:

| Файл                 | Отвечает за                                                                       |
| -------------------- | --------------------------------------------------------------------------------- |
| `README.md`          | как запустить и что за проект — для человека, впервые склонировавшего репозиторий |
| `CLAUDE.md` (корень) | неочевидные связки между воркспейсами и общий тулинг                              |
| `apps/*/CLAUDE.md`   | правила и ловушки конкретного воркспейса                                          |
| `.env.example`       | каждая переменная, которую читает код                                             |

Что чем тянет за собой:

| Изменение                                              | Обнови                                                                                                            |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| Новый воркспейс, переименование, смена порта           | таблицы пакетов в `README.md` и корневом `CLAUDE.md`, `workspaces` в `package.json`                               |
| Новый или переименованный npm-скрипт                   | таблицу скриптов в `README.md`, блок «Команды» в корневом `CLAUDE.md`                                             |
| Новая переменная окружения                             | `.env.example` воркспейса и раздел «Окружение» его `CLAUDE.md`                                                    |
| Новая страница или правка `routeRules`                 | таблицу маршрутов в `apps/web/CLAUDE.md` и раздел «Рендеринг во фронтенде» в `README.md`                          |
| Новый Elysia-плагин или модуль                         | `apps/api/CLAUDE.md`, раздел «Тулинг» в `README.md`                                                               |
| Смена палитры или токенов дизайн-системы               | раздел «Дизайн-система» в `apps/web/CLAUDE.md`                                                                    |
| Мажорное обновление зависимости (TS, Nuxt, Elysia)     | номера версий в `README.md` и обоих `CLAUDE.md`                                                                   |
| Тесты появились в новом воркспейсе или сменился раннер | раздел «Тесты» в корневом `CLAUDE.md`, раздел «Тесты» в `apps/*/CLAUDE.md`, «Скрипты» в `README.md`               |
| Новый или изменённый хук Claude Code                   | раздел «Правки агента форматирует хук» корневого `CLAUDE.md`                                                      |
| Новый MCP-сервер в `.mcp.json`                         | раздел «Playwright MCP объявлен в `.mcp.json`» корневого `CLAUDE.md`, раздел «Тулинг» в `README.md`               |
| Правка схемы `credentials` или `JWT_EXPIRES_IN` на api | `apps/web/app/utils/auth.ts` и `useAuth.ts`, раздел «Регистрация и токен» в `apps/web/CLAUDE.md`                  |
| Новый сервис или порт в `docker-compose.yml`           | раздел «База данных» в `README.md`, «Postgres живёт в compose» здесь, корневой `.env.example`                     |
| Правка `prisma/schema.prisma`                          | миграция в том же коммите (`bun run db:migrate`), раздел «База данных» в `README.md` при новой таблице            |
| Обход или ловушка, которую пришлось искать             | раздел «Ловушки, на которые уже наступали» соответствующего `apps/*/CLAUDE.md` — с причиной, не только с рецептом |

Два правила при правке:

- **Факт, ставший неверным, удаляется, а не обрастает оговоркой рядом.** Строка
  «Tailwind не подключён» после подключения Tailwind — это баг в документации.
- **Пиши причину, а не только правило.** «Не обновляй TypeScript до 7.x» без
  «потому что typescript-eslint и vue-tsc не принимают его в peer-диапазоне» —
  запрет, который снимут при первой же уборке зависимостей.

## Окружение

Bun — и пакетный менеджер, и рантайм для `api`. Node.js (>= 20.19) нужен только
Vite и Nitro внутри Nuxt, напрямую его не вызывают, кроме `start:web`
(`node .output/server/index.mjs`).

`.env` не в репозитории, рядом лежат `.env.example` в каждом воркспейсе. В корне
тоже есть `.env.example` — он только для docker-compose (`POSTGRES_*`), приложения
его не читают.

Docker нужен для Postgres: Compose v2 (`docker compose`, не `docker-compose`).

## Git

`user.name`, `user.email` и credential helper (`gh auth git-credential`) заданы
**локально** для этого репозитория — глобальный конфиг пользователя не трогай.
SSH-ключи на GitHub не зарегистрированы, push идёт по HTTPS через токен `gh`.
Remote: `https://github.com/Kiyotaka21/video-meetings.git`.
